# Варианты реализации проверки документа по чек-листу

Данные после обработки: **texts** (текст + bbox), **tables** (таблицы + ячейки), **lines** (линии), **stamps** (штампы). По выводу видно, что `stamps` пустые — детектор штампов пока не реализован.

Ниже — варианты, как по этим данным определять нарушения и **помечать места ошибок текстом**.

---

## 1. Отчёт в виде структуры «ошибка + место на странице»

**Идея:** для каждой проверки по чек-листу возвращать список нарушений с привязкой к странице и bbox (или к текстовому блоку/таблице).

**Структура результата:**
```python
@dataclass
class CheckResult:
    rule_id: int          # пункт чек-листа (1–14)
    message: str          # текст ошибки для пользователя
    page_num: int
    bbox: Optional[BBox]  # где на странице (для подсветки)
    source: str           # "stamp" | "table" | "text" | "line" | "document"
```

**Плюсы:** просто реализовать, не зависит от PDF. Удобно показывать в UI списком и подсвечивать по bbox.  
**Минусы:** «помечать текстом» = показывать текст в отчёте/интерфейсе, а не на самом листе.

**Реализация:** модуль `checker/` с правилами (функции по пунктам чек-листа), на вход — список `PageModel` + метаданные PDF (число листов, формат). Каждое правило возвращает `List[CheckResult]`.

---

## 2. Подсветка ошибок на изображении страницы (PNG)

**Идея:** рендерить страницу в картинку (как уже делается для OCR), рисовать прямоугольники в местах ошибок и подписывать их текстом (номер пункта + краткое описание).

**Как:** после прогона всех проверок для каждой страницы брать список `CheckResult` с ненулевым `bbox`, рисовать поверх изображения (PIL/OpenCV): прямоугольник + текст (например, «П.6: штамп не заполнен»).

**Плюсы:** наглядно видно «где именно» ошибка на листе.  
**Минусы:** нужен рендер каждой страницы; текст на изображении нужно аккуратно масштабировать под DPI.

**Реализация:** функция `render_page_with_errors(page_index, check_results, dpi=150)` → PNG bytes или путь к файлу. Масштабирование bbox из координат PDF в пиксели через тот же коэффициент, что и при рендере.

---

## 3. PDF с аннотациями (подсветка в PDF)

**Идея:** открыть исходный PDF (fitz/pymupdf), для каждой ошибки с известным bbox добавить аннотацию: прямоугольник подсветки + текст во всплывающей подсказке (или текстовую аннотацию).

**Как:** `page.add_redact_annot(rect, text=message)` или `add_rect_annot` + отдельная текстовая аннотация. Сохранить новый PDF (например, `album_checked.pdf`).

**Плюсы:** один файл, можно открыть в любой просмотрщике и увидеть пометки.  
**Минусы:** bbox у вас в координатах после рендера (например, 300 DPI); их нужно перевести в координаты страницы PDF (преобразование с учётом матрицы рендера).

**Реализация:** модуль `checker/annotate_pdf.py`: принять исходный PDF, список `CheckResult` с полями page_num и bbox (в единицах страницы или в пикселях при заданном DPI), добавить аннотации и сохранить новый файл.

---

## 4. Гибрид: правила + единый слой «ошибки»

**Идея:** все проверки пишут в единый слой данных (например, список `CheckResult` по всему документу). Дальше этот слой можно:
- вывести в консоль/файл (JSON, CSV);
- отдать фронту для подсветки по bbox в просмотрщике;
- передать в модуль рендера (вариант 2) или в модуль аннотаций PDF (вариант 3).

**Реализация:**  
- `checker/rules/` — по одному модулю/функции на группу пунктов чек-листа.  
- `checker/runner.py` — принимает `List[PageModel]`, вызывает все правила, собирает `List[CheckResult]`.  
- Отдельно: экспорт в JSON; рендер с ошибками; аннотированный PDF.

Так вы разделяете «что проверять» и «как показывать», и помечать ошибки текстом можно и в отчёте, и на картинке, и в PDF.

## Соответствие пунктов чек-листа и данных

| Пункт | Что проверять | Откуда брать данные |
|-------|----------------|----------------------|
| 1 | Обложка/титульник по стандарту | Тексты первой страницы, наличие ключевых фраз |
| 2 | 5 листов РВИ, наименование и шифр объекта | Количество страниц, тексты (поиск «РВИ», названия, шифра) |
| 3 | Комплектность, порядок листов | Нумерация листов в текстах/штампах vs порядок страниц |
| 4 | Ведомость: в «примечании» — кол-во листов | Таблицы, колонки «примечание» |
| 5 | Совпадение названий спецификаций в ведомости и на листах | Таблицы + тексты по страницам |
| 6 | Штампы: объект, шифр, фамилии, даты | `stamps` (когда детектор будет готов), иначе эвристики по текстам внизу страницы |
| 7 | Толщины линий таблиц/ведомостей | `lines` (width), привязка линий к bbox таблиц |
| 8 | Спецификация: строки не наезжают | Таблицы: bbox ячеек или высоты строк (если есть) |
| 9 | Диаметры и символы при печати | Сложно автоматически; можно поиск спецсимволов в текстах |
| 10 | Нет слова «варианты» в спецификации | Поиск по тексту таблиц |
| 11 | Печать по рамке | Линии рамки vs границы страницы (lines + размер страницы) |
| 12 | Формат листа | Размер страницы из PDF vs заявленный формат |
| 13 | Место под QR-код | Тексты/пустая зона в углу (эвристика по bbox) |
| 14 | Подложки: ничего лишнего/не пропало | Трудно без эталона; опционально |
